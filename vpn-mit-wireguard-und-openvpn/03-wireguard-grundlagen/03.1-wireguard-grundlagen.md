## Lernziele

Nach dieser Übung kannst du

- asymmetrische WireGuard-Schlüsselpaare generieren
- eine einfache WireGuard-Schnittstelle konfigurieren und starten

## Voraussetzungen

- Modul 2 abgeschlossen (Pakete installiert)

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Private Key / Public Key** | Schlüsselpaar; der öffentliche Schlüssel wird aus dem privaten abgeleitet (`wg pubkey`) |
| **Cryptokey-Routing** | WireGuard ordnet jedem Peer-Public-Key eine Liste erlaubter IP-Adressen zu |
| **`wg0.conf`** | Konfigurationsdatei: Abschnitt `[Interface]` (lokal) und je ein `[Peer]` |
| **`wg`** | Low-Level-Werkzeug: zeigt und ändert die Schnittstellenparameter |
| **`wg-quick`** | Skript, das Schnittstelle anlegt, Adresse und Routen setzt und `wg` aufruft |
| **`umask 077`** | neue Dateien nur für den Besitzer lesbar |

## Laborumgebung

| Was | Rolle in Modul 03 |
|---|---|
| VM 1 `vpn-a` | Debian 12, WAN `10.0.0.1/24` (Adapter `eth0`, mit `ip -br a` prüfen), simuliertes LAN Site A `192.168.10.1/24` auf `dummy0`, Benutzer `labadmin` |
| VM 2 `vpn-b` | Debian 12, WAN `10.0.0.100/24`, simuliertes LAN Site B `192.168.20.1/24` auf `dummy0` |
| Netze | WireGuard `10.8.0.0/24` (Server `.1`, Client `.100`), OpenVPN `10.9.0.0/24`, Site A `192.168.10.0/24`, Site B `192.168.20.0/24`; privater vSwitch `VPN-Lab-WAN` |
| Regel | WireGuard und OpenVPN laufen **nie gleichzeitig** (Routenkonflikt in den Netzen der Standorte) |
| Pakete | `wireguard` (enthält `wg` und `wg-quick`) |
| Dateien | `/etc/wireguard/` mit Schlüsseln (Rechte 600) und `wg0.conf` |

## Aufgabe

### Aufgabe 1 – Schlüsselgenerierung (Einheit 3.1)

Wechseln Sie mit `sudo -i` zu root und setzen Sie `umask 077`. Generieren Sie auf `VM 1` (Server) einen Private Key (`wg genkey`) und leiten Sie daraus den Public Key ab (`wg pubkey`), zum Beispiel mit `wg genkey | tee /etc/wireguard/server.key | wg pubkey > /etc/wireguard/server.pub`. Wiederholen Sie den Vorgang auf `VM 2` (Client) mit den Dateinamen `client.key` und `client.pub`.

### Aufgabe 2 – Basis-Konfiguration Server (Einheit 3.2)

Erstellen Sie auf `VM 1` die Datei `/etc/wireguard/wg0.conf`. Konfigurieren Sie den Block `[Interface]` mit der VPN-IP (`Address = 10.8.0.1/24`), dem Private Key (`PrivateKey`) und `ListenPort = 51820`. Setzen Sie die Rechte mit `chmod 600 /etc/wireguard/wg0.conf`.

### Aufgabe 3 – Dienststart (Einheit 3.3)

Starten Sie das Interface auf dem Server mit `wg-quick up wg0`. Prüfen Sie die Schnittstelle mit `ip a` und dem Befehl `wg`. Stoppen Sie es mit `wg-quick down wg0` und starten Sie es einmal über den Dienst (`systemctl start wg-quick@wg0`, Status mit `systemctl status wg-quick@wg0`, danach `systemctl stop wg-quick@wg0`). Aktivieren Sie den Autostart nicht (`systemctl enable` wird in diesem Labor nicht verwendet), damit WireGuard und OpenVPN nie gleichzeitig laufen. Starten Sie das Interface mit `wg-quick up wg0` erneut für Modul 4.

**Hinweis/Ergänzung der Ausarbeitung:** In der Testumgebung gab es kein WireGuard-Kernelmodul; `wg-quick` startete `wireguard-go` (Userspace). Statt `systemctl` wurde `wg-quick up/down` benutzt. Der Dienst `wg-quick@wg0` wurde **nicht** getestet.

## Hinweise

- Private Schlüssel nie in ein Repository, in E-Mails oder in Chatnachrichten legen.
- Die Schlüssel in den Beispielausgaben dieses Moduls sind Laborwerte einer Testumgebung und nur zur Veranschaulichung abgedruckt (der private Schlüssel wird von `wg` nicht angezeigt: `(hidden)`).
- Eine Änderung der `wg0.conf` wirkt erst nach Neustart der Schnittstelle (`wg-quick down` / `up`).
- Autostart (`systemctl enable`) wird in diesem Labor nicht verwendet, damit WireGuard und OpenVPN nie gleichzeitig laufen.

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Aufgabe 1 (Schlüsselgenerierung).**

```bash
sudo -i
umask 077
cd /etc/wireguard
wg genkey | tee server.key | wg pubkey > server.pub     # VM 1
# VM 2:  wg genkey | tee client.key | wg pubkey > client.pub
ls -l ; cat server.pub
```

Zielzustand: vier Dateien (`*.key`, `*.pub`), Rechte `-rw-------` (durch `umask 077`). Der Public Key ist eine 44 Zeichen lange Base64-Zeichenkette (Beispiel: `lDrnhvCxbiJaWyxVnX1QTgR8RdmY9kbRx8cB52PQ3AM=`, aus der Testumgebung). Befehle in der Testumgebung ausgeführt.

**Aufgabe 2 (Basis-Konfiguration Server).** `/etc/wireguard/wg0.conf` auf VM 1 (der Schlüssel wird nicht gedruckt):

```ini
[Interface]
Address = 10.8.0.1/24
PrivateKey = <Inhalt von server.key>
ListenPort = 51820
```

Dann `chmod 600 /etc/wireguard/wg0.conf`. In der Testumgebung ausgeführt.

**Aufgabe 3 (Dienststart).**

```bash
wg-quick up wg0
ip a show wg0
wg
wg-quick down wg0
systemctl start wg-quick@wg0     # nicht getestet
systemctl status wg-quick@wg0
systemctl stop wg-quick@wg0
wg-quick up wg0                  # wieder für Modul 4
```

Erwartete Ausgabe von `wg-quick up` und `wg` in der Testumgebung siehe `beispiele/m03.txt`: `wg-quick` legt die Schnittstelle an, setzt `10.8.0.1/24` und die MTU 1420; `wg` zeigt `public key`, `private key: (hidden)` und `listening port: 51820`, aber keinen Peer. Der Dienst `wg-quick@wg0` (systemd) wurde **nicht getestet**.

**Fragen.** (1) Der öffentliche Schlüssel wird aus dem privaten per Kurvenmultiplikation (Curve25519) berechnet; die Rückrichtung ist rechnerisch nicht praktikabel. Der Lehrplan nennt die Kurve nur als Begriff; hier: Fachwissen des Verfassers, nicht gegen eine Quelle geprüft. (2) `wg` konfiguriert und zeigt nur die WireGuard-Schnittstelle. `wg-quick` richtet zusätzlich alles Drumherum ein: legt die Schnittstelle an, setzt Adressen, MTU und Routen, ruft `wg setconf` auf und kann DNS-Einträge und PostUp/PostDown-Befehle ausführen (wurde in der Testumgebung beobachtet: Ausgabe `ip link add`, `wg setconf`, `ip -4 address add`, `ip link set mtu 1420 up`). (3) Schnittstellenname, den öffentlichen Schlüssel, den privaten Schlüssel nur als `(hidden)` und den Listen-Port; Peers erscheinen erst, wenn welche konfiguriert sind (in der Testumgebung geprüft).

</details>
