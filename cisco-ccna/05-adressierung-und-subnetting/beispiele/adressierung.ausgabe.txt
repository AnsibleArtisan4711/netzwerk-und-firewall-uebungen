## 4. IPv6 als Rechnung: Kurzschreibweise, EUI-64, Solicited-Node, Aufteilung /48 in /64 (im Container nicht ausgeführt)
Kurzform: 2001:db8::1  Langform: 2001:0db8:0000:0000:0000:0000:0000:0001
EUI-64 aus MAC 00:1b:63:84:45:e6 -> fe80::21b:63ff:fe84:45e6 (7. Bit des ersten Bytes invertiert, ff:fe in der Mitte)
Solicited-Node-Multicast dazu: ff02::1:ff84:45e6
Ein /48 enthält 65536 /64-Netze, z. B. 2001:db8:abcd::/64, 2001:db8:abcd:1::/64, 2001:db8:abcd:2::/64
Adresstypen: fe80::/10 Link-Local, fc00::/7 Unique Local, ff00::/8 Multicast, 2000::/3 Global Unicast, ::1 Loopback

## 6. Fehlerbilder real: Namensräume mit Router; Host A liegt in 192.168.1.0/24, Host B in 192.168.2.0/24
--- 6a. richtig konfiguriert (Vergleich)
$ ip netns exec cc5a ping -c1 -W1 192.168.2.10 | grep -E 'transmitted'
1 packets transmitted, 1 received, 0% packet loss, time 0ms
--- 6b. falsches Gateway (192.168.1.254 gibt es nicht)
$ ip netns exec cc5a ping -c1 -W1 192.168.2.10 2>&1 | grep -E 'Unreachable|transmitted'
1 packets transmitted, 0 received, 100% packet loss, time 0ms
$ ip netns exec cc5a ip neigh show 192.168.1.254 | awk '{print $1, $NF}'
192.168.1.254 INCOMPLETE
Der Host fragt per ARP nach 192.168.1.254 und bekommt keine Antwort (INCOMPLETE); die Route zeigt auf ein Gateway, das nicht existiert.
--- 6c. Maske /30 am Host: das Gateway liegt außerhalb des eigenen Netzes
$ ip netns exec cc5a ip route add default via 192.168.1.1 2>&1
Error: Nexthop has invalid gateway.
--- 6d. Maske /16 am Host: der Host hält 192.168.2.10 für direkt erreichbar und fragt per ARP statt über den Router
$ ip netns exec cc5a ping -c1 -W1 192.168.2.10 2>&1 | grep -E 'Unreachable|transmitted'
1 packets transmitted, 0 received, 100% packet loss, time 0ms
$ ip netns exec cc5a ip neigh show 192.168.2.10 | awk '{print $1, $NF}'
192.168.2.10 INCOMPLETE
--- 6e. doppelte Adresse: zwei Geräte mit 192.168.1.50 im selben Netz, Mitschnitt zeigt zwei Antworten mit verschiedenen MACs
$ ip netns exec cc5e ping -c1 -W1 192.168.1.50 | grep -E 'transmitted'
1 packets transmitted, 1 received, 0% packet loss, time 0ms
$ tshark -r dup.pcap -Y 'arp.opcode==2' -T fields -e arp.src.proto_ipv4 -e arp.src.hw_mac 2>/dev/null | sort -u
192.168.1.50	02:00:00:00:05:0c
192.168.1.50	02:00:00:00:05:0d
Zwei Antworten für dieselbe IP-Adresse mit verschiedenen MAC-Adressen: typisches Zeichen einer doppelten Adresse; der ARP-Cache des Fragenden wechselt zwischen beiden.
