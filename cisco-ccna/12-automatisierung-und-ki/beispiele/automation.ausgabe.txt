## 4. REST gegen einen Mock-Controller (Flask, lokal, kein Cisco-Produkt): Verben, Statuscodes, Token

ohne Token: HTTP 401

[{"id":1,"name":"sw-eg-01","status":"up"}]

$ ip netns exec ccrest curl -s -H X-Token:lab-token -w ' [HTTP %{http_code}]\n' -X POST -H 'Content-Type: application/json' -d '{"name":"sw-og-01","status":"up"}' http://127.0.0.1:8081/api/v1/devices
{"id":2,"name":"sw-og-01","status":"up"}
 [HTTP 201]
$ ip netns exec ccrest curl -s -H X-Token:lab-token -w ' [HTTP %{http_code}]\n' -X PATCH -H 'Content-Type: application/json' -d '{"status":"down"}' http://127.0.0.1:8081/api/v1/devices/2
{"id":2,"name":"sw-og-01","status":"down"}
 [HTTP 200]
$ ip netns exec ccrest curl -s -H X-Token:lab-token http://127.0.0.1:8081/api/v1/devices | jq -c '.[] | {name, status}'
{"name":"sw-eg-01","status":"up"}
{"name":"sw-og-01","status":"down"}
$ ip netns exec ccrest curl -s -H X-Token:lab-token -w ' [HTTP %{http_code}]\n' -X DELETE http://127.0.0.1:8081/api/v1/devices/2
 [HTTP 204]
$ ip netns exec ccrest curl -s -o /dev/null -H X-Token:lab-token -w 'GET /devices/2 nach DELETE: HTTP %{http_code}\n' http://127.0.0.1:8081/api/v1/devices/2
GET /devices/2 nach DELETE: HTTP 404
Zuordnung (Lehrbuchwissen): GET lesen, POST anlegen, PUT ersetzen, PATCH teilweise ändern, DELETE löschen; 2xx Erfolg, 4xx Fehler des Aufrufers (401 nicht angemeldet, 404 nicht gefunden), 5xx Fehler des Servers.

## 6. KI-Grundlagen als Spielzeug: Anomalieerkennung auf einer Auslastungsreihe (prädiktiv/statistisch) und Prüfung von KI-Ausgaben
Basislinie aus den ersten 60 Messwerten: Mittelwert 30.1 %, Standardabweichung 3.4
Messpunkt  90:  95.0 % -> z = 19.0 -> Auffälligkeit melden
Messpunkt  91:  88.0 % -> z = 16.9 -> Auffälligkeit melden
Das ist ein einfaches statistisches Verfahren und ein Beispiel für prädiktive/analytische KI im Betrieb: Es lernt aus Daten (hier: Mittelwert und Streuung), erkennt Abweichungen und kann Fehlalarme erzeugen.
Prüfung des KI-Vorschlags (ki_vorschlag.txt):
  Befund - Zeile 3: VLAN-ID 5000 außerhalb 1 bis 4094
  Befund - Zeile 8: Adresse 192.168.10.1 doppelt vergeben (interface Vlan10 und interface Vlan20)
  Befund - Zeile 10: VLAN 20 wird benutzt, aber nicht angelegt
Regel: Ausgaben generativer KI sind Entwürfe. Sie werden gelesen, gegen Soll und Dokumentation geprüft und erst im Labor getestet, bevor sie auf ein Gerät gehen; Betriebsdaten und Kennwörter gehören nicht in öffentliche Dienste.
