# Übung 6.1: Serielle WAN-Verbindung

| | |
|---|---|
| **Modul** | 6 – WAN und VPN |
| **Stufe** | Aufbau |
| **Geschätzte Zeit** | ca. 45–60 Minuten |
| **Werkzeug** | Cisco Packet Tracer |
| **Vorwissen** | Übung 1.2 (Router-Interfaces), Übung 3.1 (statische Routen) |

> **Stand der Prüfung:** Entwurf. Dass auf der DCE-Seite ein `clock rate` gesetzt werden muss, dass HDLC die Standard-Kapselung ist und dass `show controllers` die DCE-/DTE-Seite zeigt sowie `show interface` die Kapselung, ist durch ein Cisco-Packet-Tracer-Lab belegt (siehe Quellen). **Nicht belegt** sind die genauen Befehlssyntaxen (`clock rate 64000`, `encapsulation hdlc|ppp`), das Einsetzen des seriellen Moduls *HWIC-2T* in den Router, der Kabeltyp *Serial DCE* und welche Seite dabei DCE wird, die Schnittstellenbezeichnung `Serial0/0/0` sowie alle gezeigten Ausgaben und GUI-Wege.

## Lernziele

Nach dieser Übung kannst du

- erklären, was DCE und DTE bei einer seriellen Verbindung sind und wozu `clock rate` dient,
- in einen Router ein serielles Modul einsetzen,
- eine serielle Punkt-zu-Punkt-Verbindung mit Adressen und Taktrate einrichten,
- mit `show controllers`, `show interface` und `show ip interface brief` den Zustand lesen,
- die Kapselungen HDLC und PPP vergleichen und typische Fehler (fehlende Taktrate, ungleiche Kapselung) erkennen.

## Voraussetzungen

Interfaces und Adressen auf Routern (Modul 1), statische Routen (Übung 3.1).

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| WAN | *Wide Area Network*: Verbindung zwischen entfernten Standorten. |
| Serielle Verbindung | Punkt-zu-Punkt-Verbindung, Bits nacheinander über eine Leitung. |
| DCE / DTE | *Data Circuit-terminating Equipment* (liefert den Takt, z. B. Modem oder Provider) / *Data Terminal Equipment* (Endgerät, nimmt den Takt). Im Labor sitzt die DCE-Seite am Kabelende des einen Routers. |
| `clock rate` | Taktrate in Bit/s, die das DCE-Ende vorgibt (z. B. `64000`). |
| Kapselung | Format der Frames auf der Leitung. Bei Cisco ist HDLC Standard, PPP ist offen und kann mehr (Authentifizierung). |
| HDLC | Cisco-eigene Variante, Standard auf seriellen Interfaces. |
| PPP | *Point-to-Point Protocol*, herstellerübergreifend. |
| HWIC-2T | Steckmodul für Router der Serie 1941 mit zwei seriellen Ports. |

> **Merksatz:** Die DCE-Seite gibt den Takt vor, ohne Takt bleibt die Leitung tot. Beide Seiten müssen dieselbe Kapselung nutzen.

## Topologie und Adressplan

Zwei Router sind seriell verbunden. Jeder hat zusätzlich ein LAN mit einem PC; das Routing zwischen den Standorten folgt in Übung 6.2. Hier geht es um die Verbindung selbst.

```mermaid
flowchart LR
    R1["R1<br/>Se0/0/0: 10.0.0.1/30 (DCE)"] ---|"Serial DCE"| R2["R2<br/>Se0/0/0: 10.0.0.2/30 (DTE)"]
```

| Gerät | Port / Interface | IP-Adresse | Subnetzmaske | Rolle |
|---|---|---|---|---|
| R1 | `Serial0/0/0` | `10.0.0.1` | `255.255.255.252` | DCE (Taktgeber) |
| R2 | `Serial0/0/0` | `10.0.0.2` | `255.255.255.252` | DTE |

## Aufgabe

> **Schema dieser Übungsreihe: zwei Wege pro Schritt.** Wo es in Packet Tracer keinen CLI-Weg gibt (Geräte platzieren, Module einsetzen, verkabeln), steht das ausdrücklich dabei. Alle Befehle stehen in Codeblöcken. Die CLI-Befehle und GUI-Wege sind in dieser Entwurfsfassung noch nicht in Packet Tracer bestätigt.

**1. Neues Projekt beginnen** und zwei Router (*1941*) platzieren

- **GUI:** *File* → *New*, zwei Router aus der Geräteauswahl ziehen.
- **CLI:** Entfällt (nur grafisch möglich).

**2. Serielle Module einsetzen**

- **GUI:** Router anklicken → Reiter *Physical*. Den Netzschalter am Gerät ausschalten (Klick auf den Schalter), das Modul *HWIC-2T* aus der Modulliste in einen freien Steckplatz ziehen, den Router wieder einschalten. Danach in *Config* die Schnittstelle `Serial0/0/0` prüfen. Mache das für beide Router.
- **CLI:** Entfällt (Module werden nur grafisch eingesetzt).

**3. Seriell verkabeln**

- **GUI:** Kategorie *Connections* → *Serial DCE* (Blitz-Symbol/seriell). Zuerst R1, Port `Serial0/0/0`, dann R2, Port `Serial0/0/0` anklicken. Das zuerst angeklickte Gerät wird DCE (Annahme, bitte mit Schritt 5 prüfen).
- **CLI:** Entfällt (Kabel gibt es nur grafisch).

**4. Hostnamen und Adressen konfigurieren**

- **GUI:** Router → *Config* → *Serial0/0/0*: *IP Address* und *Subnet Mask*, *Port Status* *On*. Die Taktrate setzt du im Feld *Clock Rate* (nur am DCE-Ende, nicht bestätigt).
- **CLI:** R1:
  ```text
  Router> enable
  Router# configure terminal
  Router(config)# hostname R1
  R1(config)# interface serial 0/0/0
  R1(config-if)# ip address 10.0.0.1 255.255.255.252
  R1(config-if)# no shutdown
  R1(config-if)# end
  ```
  R2:
  ```text
  Router> enable
  Router# configure terminal
  Router(config)# hostname R2
  R2(config)# interface serial 0/0/0
  R2(config-if)# ip address 10.0.0.2 255.255.255.252
  R2(config-if)# no shutdown
  R2(config-if)# end
  ```

**5. Welche Seite ist DCE?**

- **GUI:** Das Kabelende mit Uhr-Symbol sitzt am DCE-Router (nicht bestätigt).
- **CLI:** Auf beiden Routern:
  ```text
  R1# show controllers serial 0/0/0
  ```
  Die Ausgabe nennt in einer der ersten Zeilen, ob die Schnittstelle DCE oder DTE ist (laut Lab dritte Zeile). Notiere die Seite von R1 und R2.

**6. Zustand vor der Taktrate**

- **GUI:** Das Verbindungssymbol am Kabel ist rot (nicht bestätigt).
- **CLI:**
  ```text
  R1# show ip interface brief
  ```
  Die serielle Schnittstelle steht auf `up`/`down` (Leitung erkannt, aber kein Takt/Protokoll). Notiere Status und Protokoll beider Seiten.

**7. Taktrate am DCE-Ende setzen**

- **GUI:** Entfällt auf dem Router-GUI (nur CLI, außer dem Feld *Clock Rate* oben).
- **CLI:** Am Router, der in Schritt 5 DCE war (angenommen R1):
  ```text
  R1# configure terminal
  R1(config)# interface serial 0/0/0
  R1(config-if)# clock rate 64000
  R1(config-if)# end
  ```
  Nach einigen Sekunden werden `Serial0/0/0` und das Protokoll `up`. Prüfe auf beiden Routern.

**8. Kapselung und Verbindung prüfen**

- **GUI:** *Add Simple PDU*: R1 → R2 (Router lassen sich als Quelle/Ziel wählen).
- **CLI:**
  ```text
  R1# show interface serial 0/0/0
  R1# ping 10.0.0.2
  ```
  `show interface` zeigt „Encapsulation HDLC“ (Standard, laut Lab zu prüfen) und den Zustand `up, line protocol is up`. Der Ping klappt.

**9. Gegenprobe: ungleiche Kapselung**

- **GUI:** Entfällt.
- **CLI:** Stelle R2 auf PPP um:
  ```text
  R2# configure terminal
  R2(config)# interface serial 0/0/0
  R2(config-if)# encapsulation ppp
  R2(config-if)# end
  ```
  Jetzt unterscheiden sich die Kapselungen (HDLC bei R1, PPP bei R2). Der Ping schlägt fehl und das Protokoll geht auf `down` (nicht bestätigt: die Schicht-1-Anzeige bleibt `up`).

**10. Beide auf PPP umstellen**

- **GUI:** Entfällt.
- **CLI:**
  ```text
  R1(config)# interface serial 0/0/0
  R1(config-if)# encapsulation ppp
  R1(config-if)# end
  R1# show interface serial 0/0/0
  R1# ping 10.0.0.2
  ```
  Nach einigen Sekunden steht die Verbindung wieder. In der Ausgabe von `show interface` steht jetzt PPP, meist mit LCP und IPCP im Zustand `Open` (nicht bestätigt).

**11. Gegenprobe: Takt entfernen**

- **GUI:** Entfällt.
- **CLI:** Am DCE-Router:
  ```text
  R1(config)# interface serial 0/0/0
  R1(config-if)# no clock rate
  R1(config-if)# end
  R1# show ip interface brief
  ```
  Die Leitung fällt aus (nicht bestätigt). Setze `clock rate 64000` wieder.

**12. Speichern**

- **GUI:** `Strg+S` als `06.1-serielle-wan-verbindung.pkt`.
- **CLI:**
  ```text
  R1# copy running-config startup-config
  ```

## Hintergrund: Wozu Takt und Kapselung?

1. **Synchrone Übertragung:** Auf seriellen Leitungen müssen beide Seiten im gleichen Takt senden und empfangen. Eine Seite (DCE) liefert diesen Takt.
2. **Im Labor:** Ein Kabel mit DCE-Ende simuliert den Provider. In der Praxis liefert ein Modem oder eine Anschlusseinheit des Providers (CSU/DSU) den Takt und der Router ist DTE.
3. **Kapselung:** Die Frames auf der Leitung brauchen ein Format. HDLC ist bei Cisco-Routern der Standard, aber herstellerspezifisch. PPP ist offen und kann zusätzlich Authentifizierung (PAP/CHAP).
4. **Zustandsanzeige:** `up/up` heißt Takt und Kapselung stimmen. `up/down` weist auf ein Problem auf Schicht 2 (Kapselung, fehlender Takt) hin, `down/down` auf Schicht 1 (Kabel, Modul).
5. **Zwei-Router-Subnetz:** Für eine Punkt-zu-Punkt-Verbindung reicht ein /30 mit zwei nutzbaren Adressen.

## Hinweise

- Das Modul *HWIC-2T* gehört zu den Routern der Serie 1941 und 2911. Router ohne serielle Ports brauchen das Modul, bevor `Serial0/0/0` erscheint.
- Der Router muss zum Einsetzen eines Moduls ausgeschaltet sein.
- Die Schnittstellenbezeichnung hängt vom Steckplatz ab (`Serial0/0/0`, `Serial0/0/1`, `Serial0/1/0` …). Prüfe sie mit `show ip interface brief`.
- `clock rate` wird nur auf dem DCE-Ende akzeptiert; am DTE-Ende erscheint eine Fehlermeldung.
- Beide Seiten müssen in demselben /30 liegen.

## Prüfbefehle

Am Router (CLI):

```text
R1> enable
R1# show ip interface brief
R1# show controllers serial 0/0/0
R1# show interface serial 0/0/0
R1# show running-config interface serial 0/0/0
R1# ping 10.0.0.2
```

| CLI-Befehl | Was er zeigt | GUI-Weg |
|---|---|---|
| `show ip interface brief` | Adresse, Status und Protokoll (up/down) | Router → *Config* → Interface |
| `show controllers serial <Port>` | DCE oder DTE (laut Lab dritte Zeile), Taktrate | – (nur CLI) |
| `show interface serial <Port>` | Kapselung (HDLC/PPP), Zustand, Zähler | – |
| `ping` | Erreichbarkeit der Gegenseite | *Add Simple PDU* |

**Kontrollfragen**

1. Was bedeuten DCE und DTE, und welche Seite braucht `clock rate`?
2. Was zeigt `up/down` bei einer seriellen Schnittstelle?
3. Welche Kapselung ist bei Cisco-Routern Standard?
4. Was passiert, wenn die Kapselungen der beiden Seiten nicht übereinstimmen?
5. Wie findest du heraus, welches Ende eines Kabels DCE ist?

## Erweiterungen

- **PPP mit Authentifizierung:** CHAP einrichten (`ppp authentication chap`, `username`, nicht bestätigt).
- **Zweite Verbindung:** Eine zweite serielle Strecke zwischen den Routern aufbauen.
- **Bandbreite:** `bandwidth 64` setzen und die Wirkung auf OSPF-Kosten betrachten (Übung 3.6).
- **Weiter:** Übung 6.2 verbindet damit zwei Standorte und routet über die Leitung.

**Konfiguration:**

```text
R1(config)# interface serial 0/0/0
R1(config-if)# ip address 10.0.0.1 255.255.255.252
R1(config-if)# clock rate 64000
R1(config-if)# no shutdown
```

```text
R2(config)# interface serial 0/0/0
R2(config-if)# ip address 10.0.0.2 255.255.255.252
R2(config-if)# no shutdown
```

**Vor der Taktrate (Schritt 6, sinngemäß, nicht bestätigt):**

```text
R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
Serial0/0/0            10.0.0.1        YES manual up                    down
```

**Nach der Taktrate:** Status und Protokoll `up`. `ping 10.0.0.2` klappt.

**Ungleiche Kapselung (Schritt 9):** R1 HDLC, R2 PPP, Ping schlägt fehl. Mit `encapsulation ppp` auf beiden Seiten klappt es wieder.

**Takt entfernt (Schritt 11):** Ohne Takt steht die Leitung nicht mehr auf `up/up`.

**Antworten auf die Kontrollfragen:**

1. DCE liefert den Takt (Provider-Seite), DTE nimmt ihn (Kundenseite). `clock rate` gehört auf das DCE-Ende.
2. Die physische Leitung ist erkannt (Schicht 1), das Protokoll auf Schicht 2 läuft nicht, z. B. wegen fehlender Taktrate oder verschiedener Kapselung.
3. HDLC.
4. Die Seiten verstehen die Frames der Gegenseite nicht, das Protokoll geht auf `down`.
5. Mit `show controllers serial <Port>`; die Ausgabe nennt DCE oder DTE. Im GUI zeigt das Kabelende mit Uhr-Symbol auf die DCE-Seite.
