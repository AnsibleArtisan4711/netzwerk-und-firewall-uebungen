## Lernziele

Nach dieser Übung kannst du

- Reverse Proxy, Forward Proxy und Load Balancer unterscheiden
- den Weg einer Anfrage über zwei getrennte TCP-Verbindungen beschreiben
- das Labor aufbauen und die Isolation der Backends nachweisen

## Voraussetzungen

- Netzwerkgrundlagen
- Linux-Grundlagen

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Reverse Proxy | Server vor einer oder mehreren Anwendungen, der Anfragen der Clients entgegennimmt und weiterleitet |
| Forward Proxy | Proxy auf der Seite der Clients (z. B. Firmen-Proxy für ausgehenden Verkehr) |
| Load Balancer | Verteilt Anfragen auf mehrere gleichartige Server |
| Backend / Upstream | Server hinter dem Proxy, der die eigentliche Antwort erzeugt |

## Aufgabe

### Aufgabe 1 – Labor aufbauen (Einheit 1.3)

Richten Sie `px01`, `web01`, `web02` und `cl01` nach der Laborbeschreibung ein. Weisen Sie nach, dass `cl01` die Backends direkt nicht erreicht (Ping, `curl`), den Proxy aber schon.

### Aufgabe 2 – Minimaler Proxy (Einheit 1.4)

Starten Sie nginx mit `minimal.conf` (oder führen Sie `bash proxy_konzept.sh` aus) und rufen Sie den Proxy vom Client aus auf. Was meldet das Backend als Client-Adresse?

### Aufgabe 3 – Zwei Verbindungen (Einheit 1.4)

Zeigen Sie mit `ss -tn` auf dem Proxy während einer langsamen Anfrage die zwei TCP-Verbindungen und ordnen Sie sie Client und Backend zu.

### Aufgabe 4 – Begriffe abgrenzen (Einheit 1.1)

Stellen Sie in einer Tabelle Forward Proxy, Reverse Proxy und Load Balancer nach Standort, Auftraggeber und typischer Aufgabe gegenüber.

### Aufgabe 5 – Nutzen und Risiko (Einheit 1.2)

Nennen Sie drei Vorteile und zwei Risiken eines Reverse Proxys (z. B. Single Point of Failure, Verlust der Client-Adresse).

## Hinweise

- Der Proxy leitet keine IP-Pakete zwischen den Netzen weiter (`ip_forward=0`); er öffnet für jede Anfrage eine eigene Verbindung zum Backend.
- Ohne weitere Einstellungen meldet das Backend die Adresse `10.1.2.1` (Proxy) und als Host den Namen oder die Adresse des Upstreams (siehe Modul 2).
- Die Zeitstempel im Zugriffsprotokoll sind in den Beispielausgaben durch `[Zeit]` ersetzt.

## Kontrollfragen

1. Wo steht ein Reverse Proxy im Vergleich zu einem Forward Proxy, und wem dient er?
2. Warum sieht das Backend die Adresse des Proxys und nicht die des Clients?
3. Was ist der Unterschied zwischen einem Proxy auf Schicht 7 und einem auf Schicht 4?
4. Welche Risiken entstehen durch einen zentralen Proxy?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Siehe `beispiele/proxy_konzept.ausgabe.txt`: `curl` auf `10.1.2.11:8080` liefert HTTP 000 (keine Verbindung).
2. Das Backend meldet `client=10.1.2.1` (die Adresse des Proxys).
3. `ss` zeigt `10.1.1.1:80 ↔ 10.1.1.2:…` (Client) und `10.1.2.1:… ↔ 10.1.2.11:8080` (Backend).
4. Forward Proxy: beim Client, für ausgehenden Verkehr; Reverse Proxy: beim Server, für eingehenden Verkehr; Load Balancer: Verteilung, oft derselbe Dienst.
5. Vorteile: ein Einstiegspunkt, TLS zentral, Verteilung, Schutz, Caching; Risiken: Ausfall des Proxys, Client-Adresse geht verloren, Fehlkonfiguration wirkt auf alle.

**Kontrollfragen (Antwortskizzen):**

1. Ein Reverse Proxy steht vor den Servern und dient dem Betreiber der Anwendung; ein Forward Proxy steht bei den Clients und dient diesen.
2. Die TCP-Verbindung zum Backend baut der Proxy auf; deshalb ist seine Adresse die Quelle.
3. Schicht 7 versteht HTTP (Host, Pfad, Header, Cookies); Schicht 4 reicht nur Bytes einer TCP-Verbindung durch.
4. Ausfall betrifft alles; Fehler in der Konfiguration wirken auf alle Anwendungen; der Proxy sieht den Klartext nach der TLS-Terminierung.

</details>
