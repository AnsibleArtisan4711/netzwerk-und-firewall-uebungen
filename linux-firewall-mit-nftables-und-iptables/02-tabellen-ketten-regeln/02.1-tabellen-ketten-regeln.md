## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| Familie | Protokollfamilie einer Tabelle: `ip`, `ip6`, `inet` (beides), `arp`, `bridge`, `netdev` |
| Handle | laufende Nummer einer Regel, mit `nft -a` sichtbar und zum Löschen nutzbar |
| policy | Standardentscheidung einer Basis-Kette, wenn keine Regel trifft |
| Priorität | Reihenfolge von Basis-Ketten desselben Hooks (kleinere Zahl zuerst) |

## Aufgabe

### Aufgabe 1 – Tabelle und Kette (Einheit 2.1)

Legen Sie in `fw01` eine Tabelle `inet demo` mit Basis-Kette `input` (policy accept) an und zeigen Sie sie mit `nft -a list table inet demo`.

### Aufgabe 2 – Reihenfolge (Einheit 2.2)

Fügen Sie eine Regel für Port 22 an das Ende (`add`) und eine für das Loopback an den Anfang (`insert`) an. Erklären Sie, warum die Reihenfolge wirkt.

### Aufgabe 3 – Regel löschen (Einheit 2.2)

Löschen Sie die Regel für Port 23 anhand des Handles (aus `nft -a`).

### Aufgabe 4 – Skript lesen (Einheit 2.3)

Führen Sie `bash nft_grundlagen.sh` aus und erklären Sie jede Ausgabe in eigenen Worten.

### Aufgabe 5 – Sprung und Fehlermeldung (Einheit 2.4)

Legen Sie eine reguläre Kette `web` an, springen Sie mit `jump web` hinein und versuchen Sie, `web` zu löschen. Welche Meldung kommt, und warum?

## Hinweise

- `insert` setzt vor die erste Regel (oder vor die angegebene), `add` ans Ende.
- Eine Kette, auf die noch eine `jump`-Regel zeigt, ist „busy“ und lässt sich nicht löschen (Beobachtung im Lauf).
- `delete table` entfernt die Tabelle samt Inhalt; ohne Rückfrage.

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. `nft add table inet demo; nft add chain inet demo input '{ type filter hook input priority 0; policy accept; }'`.
2. Regeln werden von oben nach unten ausgewertet, die erste treffende mit endgültigem Urteil (accept/drop) gewinnt.
3. `nft -a list chain inet demo input` zeigt `# handle N`; dann `nft delete rule inet demo input handle N`.
4. Siehe `beispiele/nft_grundlagen.ausgabe.txt`.
5. „Device or resource busy“: Die Kette wird noch von einer Regel referenziert; erst die `jump`-Regel löschen.

**Kontrollfragen (Antwortskizzen):**

1. Eine Basis-Kette hängt an einem Hook und bekommt Pakete vom Kern; eine reguläre Kette wird nur über jump/goto erreicht.
2. Wenn dieselben Regeln für IPv4 und IPv6 gelten sollen (eine Tabelle statt zwei).
3. Mit `nft -a list` den Handle ablesen und `nft delete rule <tabelle> <kette> handle <n>` ausführen.
4. Pakete, die keine Regel trifft, werden verworfen.

</details>
