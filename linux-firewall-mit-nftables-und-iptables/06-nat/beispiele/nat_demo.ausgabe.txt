
## 1. Ohne NAT: der Server sieht die echte Client-Adresse
$ on cl curl -s -m 2 http://10.0.2.2:8080/
Quelle: 10.0.1.2

## 2. Source-NAT: masquerade für alles, was über v-fw2 hinausgeht
$ on cl curl -s -m 2 http://10.0.2.2:8080/
Quelle: 10.0.2.1
$ on fw conntrack -L -p tcp
conntrack v1.4.8 (conntrack-tools): 1 flow entries have been shown.
tcp      6 119 TIME_WAIT src=10.0.1.2 dst=10.0.2.2 sport=42552 dport=8080 src=10.0.2.2 dst=10.0.2.1 sport=8080 dport=42552 [ASSURED] mark=0 use=1

## 3. Port-Weiterleitung: Aufrufe an 10.0.1.1:8000 landen beim Server 10.0.2.2:8080 (DNAT in prerouting)
$ on cl curl -s -m 2 http://10.0.1.1:8000/
Quelle: 10.0.2.1

## 4. Ohne passende forward-Regel scheitert das Weiterleiten trotz DNAT, sobald die Firewall verwirft
$ on cl curl -s -m 2 http://10.0.1.1:8000/
Quelle: 10.0.2.1
$ on cl curl -s -m 2 -o /dev/null -w direkt zu 10.0.2.2:8080 -> HTTP %{http_code}\n http://10.0.2.2:8080/
direkt zu 10.0.2.2:8080 -> HTTP 000
direkt zu 10.0.2.2:8080 -> verworfen (nicht per DNAT)

## 5. Redirect: Aufrufe an Port 9000 der Firewall selbst auf den lokalen Port 3128 umleiten
$ on cl curl -s -m 2 -o /dev/null -w HTTP-Status von 10.0.1.1:9000: %{http_code}\n http://10.0.1.1:9000/
HTTP-Status von 10.0.1.1:9000: 200

## 6. NAT-Tabelle mit Zählern
table ip nat {
	chain post {
		type nat hook postrouting priority srcnat; policy accept;
		oifname "v-fw2" counter packets 3 bytes 180 masquerade
	}

	chain pre {
		type nat hook prerouting priority dstnat; policy accept;
		iifname "v-fw1" tcp dport 8000 counter packets 2 bytes 120 dnat to 10.0.2.2:8080
		iifname "v-fw1" tcp dport 9000 redirect to :3128
	}
}
